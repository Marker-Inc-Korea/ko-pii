# Compatibility Contract / 호환성 정책

## 지원 표면

1.x에서는 `ko_pii.__all__`에 공개한 이름과 문서화된 코어 메서드를 유지하는 것을
원칙으로 합니다. 선택 의존성의 upstream 변경은 별도 영향을 줄 수 있습니다.
밑줄로 시작하는 함수·모듈 내부 구현·연구 스크립트는 안정 API가 아닙니다.
문서에 사용법이 있다는 이유로 모든 하위 모듈 심볼이 공개 계약이 되지는 않습니다.

기존 호출에 필수 인자를 추가하거나 위치 인자 순서를 바꾸는 변경은 호환성 변경으로
취급합니다. 보안상 잘못된 입력을 거부하는 강화는 patch/minor에 들어갈 수 있으며
CHANGELOG에 마이그레이션 안내를 적습니다. 선택 인자 추가는 기존 기본 동작을 유지합니다.
제거가 필요하면 먼저 문서와 경고로 폐기를 알리고 다음 major에서 제거하는 것이 원칙입니다.

탐지 규칙·사전의 개선으로 탐지 결과와 토큰 부여 순서는 달라질 수 있습니다.
기존 토큰 문자열을 전체 버전에 걸친 영구 식별자로 취급하지 마세요.
같은 Vault 상태에서 같은 (라벨, 원문) 쌍을 재사용하는 계약과는 별개입니다.
업그레이드 전 자체 라벨셋·정책으로 출력 회귀를 확인하세요.

## CLI

`ko-pii`의 문서화된 옵션은 위 호환 원칙을 적용합니다.
일반 처리는 성공 0, 처리 실패 1, 인자·설정 오류 2를 구분합니다.
평가 CLI는 회귀 임계값 실패에 별도 비정상 종료를 사용할 수 있으므로 해당
`--help`와 평가 문서를 따르세요. stderr의 사람용 문장을 파싱하는 것은 지원하지 않습니다.

## JSON과 좌표

보고서는 각 문서의 `schema_version` 또는 `contract`를 확인해 소비합니다.
패키지 버전과 보고서 계약 버전은 별개입니다. 기존 필드의 의미를 바꾸거나 필수 필드를
제거할 때는 해당 계약을 변경합니다. 소비자는 추가 출력 키를 허용해야 합니다.
반대로 설정 입력(PolicyProfile 등)은 오타 방지를 위해 알 수 없는 키를 거부할 수 있습니다.
기존 포맷에 버전 필드가 없다면 소비 전에 버전별 가이드를 확인하고 임의 추정을 하지 마세요.

탐지 span은 Python 문자열의 문자 인덱스, 반개구간 [start, end)입니다.
바이트 위치나 JavaScript UTF-16 인덱스가 아닙니다. 정규화 탐지는 원문 좌표로 복원합니다.
값 없는 보고서도 위치·라벨·길이 정보를 포함하므로 공개 전에 민감성을 판단하세요.

## Vault와 정책 파일

Vault JSON schema 1과 PolicyProfile schema 1의 유효한 기존 파일을 읽을 수 있도록 검사합니다.
미지원 schema, 중복/충돌 매핑과 손상된 값은 거부하며 자동 보정·묵시적 재번호를 하지 않습니다.
암호화 파일과 키 관리 범위는 [Vault 보안](VAULT_SECURITY.md)을 참고하세요.
JSON Vault는 평문 개인정보를 담습니다. fixture의 값은 합성이며 운영 Vault를 커밋하면 안 됩니다.

1.22.0 PyPI wheel로 만든 고정 fixture는 export·생성자 호출 형태·Vault 복원과 다음 토큰·
정책 fingerprint·EMAIL 설명 좌표·CLI 출력을 검사합니다.
이것은 유용한 회귀 감지 장치이지 모든 과거 버전/모든 API 조합의 호환성 증명은 아닙니다.
서로 다른 버전의 동일 탐지율 또는 모든 선택 모델의 재현성도 보장하지 않습니다.

## 보안 지원

수정은 최신 1.x 릴리스에 제공하며, 모든 과거 minor에 병렬 backport를 약속하지 않습니다.
취약점 대응과 보고 채널은 [SECURITY](../SECURITY.md)가 기준입니다.
