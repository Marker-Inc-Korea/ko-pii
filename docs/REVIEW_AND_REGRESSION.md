# 검토 기록과 회귀 검증

이 문서는 `1.20.0`의 변경 사항입니다.

## 피드백 철회

`apply_feedback()`는 현재 verdict를 기준으로 다음 세 파일을 다시 만듭니다.

- `common_words_additions.txt`: 반복된 PERSON FP 후보
- `names_to_add.txt`: PERSON FN 후보
- `summary.json`: 현재 건수와 후보 목록

FP/FN을 OK로 바꾸고 다시 실행하면 이전 후보가 파일에서도 제거됩니다. 후보가 없어도
파일은 설명 주석만 담은 상태로 갱신됩니다. 사용자가 같은 파일에 직접 적은 줄도 재생성 시
덮어쓰므로 수동 사전은 다른 파일에 두십시오. 이 세 파일 외의 파일은 삭제하지 않습니다.
제외 목록을 이미 메모리에 올린 Anonymizer는 새 파일을 읽어 다시 생성해야 합니다.
이름 후보의 자동 학습/반영은 하지 않습니다.

각 파일은 임시 파일을 거쳐 atomic replace로 교체하지만 세 파일을 하나의 트랜잭션으로
묶지는 않습니다. 쓰기 오류가 나면 이전/새 파일이 섞일 수 있으므로 결과를 적용하지 말고
오류를 해결한 뒤 다시 생성하십시오. 후보 파일과 큐에는 원문이 있으므로 보호가 필요합니다.

## 손상된 큐

JSON 문법/스키마 오류, 중복 ID/키, 잘못된 span/confidence/verdict가 있으면 줄 번호를
포함한 오류를 반환하고 원본 파일을 덮어쓰지 않습니다. 유효한 행만 골라 로드한 뒤 나머지를
삭제하던 동작은 더 이상 하지 않습니다. 알 수 없는 필드도 조용히 버리지 않고 거부합니다.

`mark()`는 파일 교체에 성공해야 메모리 verdict를 갱신합니다. 큐 끝에 개행이 없는 정상
파일에도 새 레코드가 붙지 않도록 구분자를 넣습니다. 원문 값은 오류 메시지에 넣지 않습니다.
수정은 원본을 백업한 뒤 호출자가 수행해야 하며 자동 복구는 제공하지 않습니다.

이는 단일 작성자의 파일 큐입니다. 동시 쓰기 잠금이나 프로세스 간 병합은 제공하지 않습니다.
append 도중 저장 장치 오류/프로세스 종료가 나면 마지막 행이 손상될 수 있습니다. 다음
로드에서 이를 오류로 반환하지만 append 전체를 트랜잭션으로 보장하지는 않습니다.

## 탐지 0건의 해석

결합 위험도는 **선택된 탐지 라벨**에 적용하는 라이브러리 휴리스틱입니다. 원문 전체의
안전성, 개인정보 부재, 법적 익명성을 판정하지 않습니다. 기존 숫자 임계값은 유지합니다.
요약의 `detection_scope`에 빈 입력인지, 명시 필드 단언인지, include/exclude 범위를 남깁니다.
미탐, 지원하지 않는 라벨, 제외된 범위까지 검사했다고 해석하면 안 됩니다.

## 회귀 시나리오

```bash
python -m pytest -q tests/unit/eval/test_domain_scenarios.py \
  tests/unit/patterns/test_phone_prefix_matrix.py \
  tests/unit/review/test_review_integrity.py
```

신청서·대화·자유 서술을 나눈 17개 수작업 합성 사례에서 라벨/좌표와 STRICT + redact의
실제 치환 상태를 확인합니다. 반복 값은 누적 길이로 좌표를 만들며 첫 문자열 검색 결과를
재사용하지 않습니다. 이 사례는 규칙 수정에 사용한 회귀 검사이지 독립 정확도 벤치마크가
아닙니다. 실제 업무 문서 전체로 일반화하지 마십시오.

제품 코드에 포함된 전화번호 모양 문자열의 오탐, 미래 생년월일 합성 RRN의 미탐도 별도로
기대값에 남깁니다. 테스트를 skip/xfail로 숨기지 않으며 탐지 동작이 바뀌면 확인을 요구합니다.
정상 연락처를 놓칠 수 있는 전역 영문 경계 필터나 날짜 검사를 없애 점수만 높이지 않습니다.

전화번호 검사는 010/011/016/017/018/019, 국내/국제/괄호 표기, 구분자, 가입자 번호 길이를
조합합니다. 이는 과거 문서 형식의 탐지 지원이며 실제 개통/할당된 번호라는 인증은 아닙니다.

평가 보고서의 `evaluation_date`는 실행 환경의 로컬 날짜입니다. 일부 생년월일 규칙이
현재 날짜를 사용하므로 서로 다른 날짜의 결과 차이가 항상 코드 회귀는 아닙니다. 자동으로
비교를 막지는 않습니다. 회귀 테스트의 미래 RRN 사례만 검사 기준일을 고정합니다.
