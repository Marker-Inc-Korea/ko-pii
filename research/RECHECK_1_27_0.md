# 1.27.0 HTML 검토 기록 재검사

2026-11-18, Python 3.12.3. 원문 검토 리포트의 문서 대응과 피드백 다운로드를 수정했습니다.
탐지·치환 규칙, Vault 형식, 코어 런타임 의존성·모델/OCR은 변경하지 않았습니다.

## 재현한 문제

실제 설치한 1.26.1에서 서로 다른 위치의 같은 RRN 두 건이 REVIEW인 경우를 확인했습니다.
첫 위치를 OK, 두 번째를 FP로 표시하면 화면은 별개로 보였지만 JSON에는 마지막 FP 하나만
남았습니다. 값/토큰을 객체 키로 사용해 서로 다른 위치를 합친 것이 원인이었습니다.

다른 문서의 원문과 처리 결과를 조합해도 HTML이 생성됐고, 처리 결과에 들어 있던 별도
문서의 PII가 잘못된 원문 패널에 표시됐습니다. 또한 이전 피드백의 키는 원문 값을 포함할
수 있어 다운로드 파일도 민감했습니다.

## 수정과 계약

- 보고서를 만들기 전에 모든 탐지의 값·좌표와 원문이 일치하는지 검사합니다. 치환 좌표와
  치환하지 않은 앞뒤 본문까지 확인하므로 PII만 같은 다른 문서도 오류입니다. 오류는 원문을
  복사하지 않습니다. 이는 대응 검사이며 결과 작성자 인증이나 위조 방지 서명은 아닙니다.
- 같은 값을 위치별로 독립 검토하고 동일 위치의 판정 변경만 갱신합니다. 새 다운로드는
  `ko-pii-html-review-marks-v1`의 버전·보고서 ID·위치별 항목을 사용합니다.
- 원문 값·토큰·사용자 문서 ID는 피드백 JSON에 복사하지 않습니다. 자유 문자열인 사용자
  정의 라벨은 `UNKNOWN`으로 내보냅니다. 좌표·라벨·길이도 내부 정보일 수 있습니다.
- 원문이 포함되는 HTML 자체에는 명시적인 주의 문구를 표시합니다. 좁은 화면은 비교
  패널을 세로 배치하고 검토 버튼을 키웁니다. 외부 CSS·JavaScript·API 요청은 없습니다.
- FP/OK는 선택한 위치에 대한 사람의 판단입니다. 미탐 검사·검토 완료 승인·정책이나
  사전 자동 변경·ReviewQueue 자동 반영으로 확대하지 않습니다.

기존 호출 형태는 유지하지만 다운로드 JSON 형식은 바뀝니다. 과거 HTML은 생성 당시
스크립트를 그대로 가지며 자동 갱신되지 않습니다. 버전 없는 과거 값별 매핑으로는 반복 값의
위치를 복원할 수 없으므로 무손실 자동 변환하지 않습니다. [전환 안내](../docs/HTML_REVIEW.md)를
따라 원본에서 다시 생성·검토하거나 소비 코드를 새 계약에 맞춰 수정해야 합니다.

## 확인한 동작

- 위치별 상반된 판정과 한 위치만 다시 표시하는 JavaScript를 실제 실행해 확인합니다.
  Node.js가 없는 환경은 해당 JavaScript 실행 검사를 생략하며 성공으로 계산하지 않습니다.
- 잘못된 원문/가명문, 치환하지 않은 본문 차이, 손상되거나 빠진 치환 좌표·동작을
  거부합니다. Unicode 원문과 네 처리 모드·여섯 전략의 정상 보고서는 유지합니다.
- 사용자 HTML 문자열과 위험도 문자열을 실행하지 않고, 사용자 문서 ID·토큰·원문과
  자유 라벨 문자열이 피드백으로 복사되지 않는지 검사합니다.
- Chromium 159.0.8154.6에서 생성 HTML을 직접 열어 클릭·판정 변경·Blob JSON 다운로드,
  선택 상태·건수, 1,360px/412px 화면을 확인했습니다. 페이지 오류와 외부 HTTP 요청은
  없었습니다. 합성 입력의 로컬 브라우저 검사이며 모든 브라우저의 호환성 보장은 아닙니다.
- 문서의 Python 예제도 설치 wheel에서 실행합니다. 예제 문서를 source archive의 필수
  자산으로 검사하고 새 보고서 검사를 Windows/macOS 배포 검사에 포함합니다.

제품 Python 158개 파일의 상대 POSIX 경로 순서에 대해 `경로 + NUL + 내용 + NUL`을
결합한 SHA-256은 `529b18d24b35740354798e93b8c03ad7c5873b230565a049a6a9352355313ea0`입니다.
1.26.1 대비 제품 변경은 버전 선언과 `reporting/html_report.py`뿐입니다. 최종 배포의
검사 결과와 파일 해시는 GitHub Actions와 `distribution-manifest.json`에서 확인합니다.

이번에는 외부 탐지 벤치마크를 재실행하거나 탐지율 향상을 주장하지 않습니다. 기존 측정은
[1.26.1 기록](RECHECK_1_26_1.md)에 있으며, 고객의 실제 문서·필수 라벨·허용 미탐/과다
마스킹·복원 권한과 승인 기준의 검증은 여전히 별도입니다. 이 수정만으로 사업 적용이나
법적 익명성 판단이 완료됐다고 주장하지 않습니다.
