# 1.25.0 명시적 다국어 이름 필드 재검사

2026-11-18, Python 3.12.3. 사람 전용 필드에서 지원하던 2~4음절 한글 이름 외에
긴 한글·띄어 쓴 이름·영문·한자·괄호 병기를 보완했습니다. 새 모델·외부 API·코어
런타임 의존성을 추가하거나 일반 문장의 NER 기준을 일괄 완화한 변경은 아닙니다.

## 재현과 처리 범위

기존 배포 1.24.1은 `성명: 장피에르뒤퐁`, `성명: 김 민수`, `성명(영문): John Smith`,
`성명(한자): 金民秀`를 놓쳤고 `성명: 김민수(金民秀)`에서 한자 표기를 남겼습니다.
새 구현은 `성명`/`성함`이라는 사람 전용 신호와 지원 이름 형태를 함께 확인합니다.
확인한 정확한 값은 같은 문서의 앞뒤 등장에도 단어 경계로 재사용합니다.

같은 공개 처리 검사 151개에서 설치한 1.24.1은 126개 실패/25개 통과했고 새 구현은
모두 통과했습니다. 이름·표기·정책·Unicode·경계 조합 수이지 독립 결함 126개나 실제
업무의 정확도를 뜻하지 않습니다. 별도로 생성형 순회 oracle과 Unicode 원문 범위,
제외어·다른 호출로의 문맥 비전파와 다수 고유 이름의 CPU 확장을 검사합니다.

최종 제외어 검사에서 복합 성씨가 있는 전체 이름을 제외해도 기존 경로가 성씨 부분만
다시 가리는 오류를 발견했습니다. 제외된 정확한 필드값과 지원 반복 구간에서 부분 후보가
우회하지 않도록 수정했습니다. 같은 문서의 별도 이름까지 전역 허용하지 않는 회귀와
대량 제외어 비용도 확인합니다. 이 오류가 있던 중간 구현의 검사는 최종 통과에 합산하지 않습니다.

`__John Smith__` 같은 직접 필드값은 강조 밖 단어 경계와 혼동하지 않고 처리하지만,
본문의 `XJohn Smith`/`John SmithX` 속 조각을 새로 가리지 않습니다. 확장 문법의 닫히지
않은 인용 빈 항목으로 목록 문맥을 넘기지 않으며 인용부호 안의 공백은 보존합니다.
숫자·밑줄 식별명, 다음 줄·셀·세미콜론으로 이어진 임의 값을 추측 연결하지 않습니다.
정규화 뷰의 항목당 최대 128자이며 초과 값의 앞부분을 완전한 이름으로 주장하지 않습니다.
미지원 값과 스키마가 확정된 입력은 기존의 구조화 필드 단언·업무 규칙을 사용해야 합니다.

레거시 `origin`은 문자열 형태 태그이며 국적·실제 출신·보호 대상 판정이 아닙니다.
기본 마스킹은 `foreign`/`unknown`을 이유로 이름을 제외하지 않습니다. 잘못 해석할 수
있는 내부 설명을 수정했으며 태그 반환값과 역사적 KLUE 표본 필터는 바꾸지 않았습니다.

[지원 문법과 호환성 안내](../docs/SCOPED_RULES_AND_TRACE.md)를 참고하세요.

## 검증 경계

- API·CLI·JSON·정책 프로필·버퍼 입력의 실제 치환, 반복 토큰과 Vault 복원을 확인합니다.
  값 없는 설명 보고서는 기존 허용 목록만 내보내며 임의 evidence나 이름을 포함하지 않습니다.
- 설치 wheel의 RAG/MCP 33개, 최소 MCP 1.28.1/2.0.0의 실제 stdio 각 19개,
  Presidio 규칙 연동 6개 통과/환경 반대 조건 1개 생략입니다. 생략은 통과에 합산하지 않습니다.
- 선택 MCP SDK 설치/미설치의 전체 157개 소스 타입 검사와 린트가 통과했습니다.
  설치한 core-only 환경의 API 호출을 네트워크 차단 상태에서도 확인했고, 별도 CLI와
  Vault 복원 및 README 예제도 검사했습니다. 네트워크 차단은 호출 API 검사 범위이며
  호스트 전체의 네트워크 통제를 의미하지 않습니다.
- 설치 wheel의 고정 seed 0~3 합성 회귀 하한을 모두 통과했습니다. 이 표본의 성공은
  새로운 블라인드 평가나 고객 환경의 탐지율이 아닙니다.
- 제품 `.py` 157개를 패키지 상대 POSIX 경로 순으로
  `경로 + NUL + 파일 내용 + NUL`로 결합한 SHA-256은
  `fb3e097e1ac6db783c5529125eaa790c4a3d4779559019e358e76bebed51e1b7`입니다.
  소스·설치 wheel·core-only 설치가 일치하며 외부 비교 후 제품 코드는 변경하지 않았습니다.

전체 소스·설치 wheel·소스 아카이브의 회귀와 선택 SDK, Windows/macOS CLI 검사는
필수 배포 파이프라인에서 실행합니다. 테스트 결과와 배포 파일 해시는 해당 태그의
GitHub Actions 및 `distribution-manifest.json`에서 확인할 수 있습니다.

## 고정 외부 합성 회귀와의 비교

[고정 프로토콜](external-protocol.json)의 K-PII-Bench Track A, CC-BY-4.0, 같은
리비전·해시·14개 대응 라벨·STRICT/redact를 유지했습니다. 0~2999는 이미 관찰한
회귀 자료이며 새 블라인드 평가나 실제 고객 문서 검증이 아닙니다.

| 해시 순위 | 1.24.1 strict F1 | 1.25.0 strict F1 | 완전히 치환되지 않은 gold 구간 (두 버전) |
|---|---:|---:|---:|
| 0~499 | 0.559277 | 0.559277 | 886 |
| 500~999 | 0.546907 | 0.546907 | 950 |
| 1000~1499 | 0.554873 | 0.554339 | 911 |
| 1500~1999 | 0.562243 | 0.562243 | 939 |
| 2000~2499 | 0.558225 | 0.557702 | 939 |
| 2500~2999 | 0.555470 | 0.555470 | 887 |

문서·라벨·좌표별 비교에서 PERSON의 새 strict FN 2개/FP 2개, 해소 FN·FP 각 0개입니다.
두 값 모두 기존 4음절 이름 뒤에 붙은 한 글자 조사까지 5음절 필드 전체로 보호한 경우입니다.
긴 실제 이름의 마지막 음절을 남기지 않는 정책과 경계 모호성의 대가이며, benchmark의
점수를 맞추기 위해 이름을 4음절로 다시 제한하지 않았습니다. 출력의 새/해소 잔존은
각 0개입니다. 단어 경계가 더 정확해졌거나 일반 NER 성능이 개선됐다고 주장하지 않습니다.

전체 gold 11,522개 중 완전히 치환되지 않은 구간은 두 버전 모두 5,512개입니다.
정책상 보존·부분 치환이 포함되므로 이것을 유출률로 해석하지 않습니다. 새 필드 처리만으로
일반 문장 PERSON/ADDRESS의 재현율이나 업무 전체의 개인정보 제거가 해결된 것은 아닙니다.

```bash
python scripts/evaluate_external.py --cache /tmp/ko-pii-external \
  --rank-start 0 --output /tmp/ko-pii-1.25.0-ranks-0.json
```

500/1000/1500/2000/2500도 같은 방식입니다. 최초 다운로드에만 `--download`를 명시하고
두 버전의 환경·출력 경로를 분리해 기존 측정을 보존합니다. 업그레이드 전 필수 라벨의
미탐·과다 마스킹·최종 출력 잔존, 문서 추출 범위와 복원 권한을 실제 업무 자료로 검증하세요.
이 기록은 고객 환경의 사업 적용 승인이나 법적 익명성 판정이 아닙니다.
