# 1.26.0 양식 경계와 표 헤더 재검사

2026-11-18, Python 3.12.3. 한 줄 양식에서 이름을 놓치거나 항목명을 흡수하던 문제,
표의 생년월일 열 누락과 Unicode 헤더 미매핑을 수정했습니다. 모델·OCR·외부 호출이나
새 코어 런타임 의존성을 추가하지 않았습니다.

## 재현한 문제

실제 배포 1.25.0에서 다음 동작을 확인했습니다.

- `성명: John Smith 전화번호: ...`와 강조한 다음 필드에서는 이름이 그대로 남았습니다.
  `성명: 김빛나라 전화번호: ...`에서는 마지막 음절 `라`가 남았습니다.
- `성명: John Smith 생년월일(양력): ...`는 이름뿐 아니라 다음 항목명과 설명까지
  PERSON으로 흡수했습니다. 알려진 주체가 붙은 `고객 연락처`와 강조 조합도 경계가 불완전했습니다.
- `anonymize_records()`의 `생년월일`·`DOB` 헤더는 미매핑이어서 셀이 원문 그대로였습니다.
- NFD `전화번호`, 전각 `ｅｍａｉｌ`, zero-width가 낀 `email`도 미매핑돼 원문이 남았습니다.

새 구현은 표와 텍스트 경계에 공유 사전을 사용하고, 명확한 생년월일 별칭을 추가합니다.
매핑용 헤더만 기존 Unicode 정규화로 비교하고 출력 키나 원래 입력은 수정하지 않습니다.
알 수 없는 혼합 헤더는 기본 정책에서 계속 미매핑이며, 이름 뒤 경계 인식만으로 다음
필드의 값을 자동 PERSON/다른 라벨로 단언하지 않습니다.

알려진 주체 접두사, 짝이 맞는 프레임과 같은 줄의 32자 이내 괄호 설명을 지원합니다.
대괄호·강조 문자라는 이유만으로 임의 값을 정상 필드로 추측하지 않습니다. 기존 표의
98개 별칭과 순서는 검증한 공개 1.25.0 wheel의 고정 snapshot과 대조합니다.
표의 생년월일은 스키마 단언이지 실제 날짜·신원 검증이나 양력/음력 변환이 아닙니다.

## 검증 범위

- 같은 공개 처리 조합 562개에서 설치한 1.25.0은 382개 실패/180개 통과했고 새 구현은
  모두 통과했습니다. 표기·모드·헤더·원문 좌표 조합 수이며 독립 결함 382개나 실제 정확도가 아닙니다.
- 소스 전체 4,970개 통과/15개 생략, 별도 설치 wheel 4,955개 통과/30개 생략입니다.
  생략은 통과에 합산하지 않습니다. 새 경로뿐 아니라 기존 회귀도 함께 실행합니다.
- 설치 wheel의 RAG/MCP 33개, 최소 MCP 1.28.1/2.0.0의 실제 stdio 각 19개,
  Presidio 규칙 연동 6개 통과/환경 반대 조건 1개 생략입니다.
- 생성형 문법/Unicode 원문 좌표와 출력 바깥 문자 보존, 원래 헤더 키 보존·별도 키 비병합,
  exact/normalized 분류 근거, 잘못된 셀 타입의 Vault 쓰기 전 거부를 확인합니다.
  긴 공백·깨진 다음 필드와 조밀한 양식의 CPU 확장을 검사하며 절대 처리량 보장은 아닙니다.
- API·JSON·정책 프로필·버퍼·CLI·CSV와 Vault 복원을 확인했습니다. 코어만 설치한 별도
  환경에서 API 통신을 차단한 검사도 통과했습니다. 이 차단은 API 검사 범위이며 호스트
  전체 네트워크 통제를 의미하지 않습니다. 설치 패키지의 새 양식·표 예제도 실행합니다.
- 선택 MCP SDK 설치/미설치의 158개 소스 타입 검사와 린트가 통과했습니다.
  제품 `.py`를 상대 POSIX 경로 순서로 `경로 + NUL + 파일 내용 + NUL`로 결합한
  SHA-256은 `6a9bc985441867667bc0131accb5759df3f77258627d329624d818451cc8efb0`입니다.
  소스와 설치 wheel이 일치하며 외부 비교 후 제품 코드는 변경하지 않았습니다.

소스 아카이브·설치 wheel·선택 SDK와 Windows/macOS CLI는 필수 배포 파이프라인에서도
검사합니다. 배포 태그의 GitHub Actions와 `distribution-manifest.json`으로 결과와
실제 배포 파일 해시를 확인할 수 있습니다.

## 기존 외부 합성 자료

[고정 프로토콜](external-protocol.json)의 K-PII-Bench Track A, CC-BY-4.0, 같은 리비전·
해시·14개 대응 라벨·STRICT/redact를 유지했습니다. 0~2999는 이미 본 회귀 자료이며
새 블라인드 평가나 고객 문서 검증이 아닙니다.

3,000문서의 문서·라벨·좌표별 비교에서 새/해소 strict FN·FP와 새/해소 출력 잔존은
각 0개입니다. 각 500건의 F1과 출력 집계는 [1.25.0 기록](RECHECK_1_25_0.md)과 같습니다.
gold 11,522개 중 완전히 치환되지 않은 구간도 두 버전 모두 5,512개입니다. 정책상 보존·
부분 치환이 포함되므로 유출률로 해석하지 않습니다.

이 자유 텍스트 평가는 표 헤더 매핑을 직접 평가하지 않으며 모든 새 양식 구문도 포함하지
않습니다. 결과가 같다는 것을 일반 PERSON/ADDRESS 성능 개선이나 실제 업무의 무미탐
증거로 쓰지 않습니다. 표·양식 경로는 별도의 공개 API 회귀로 검증합니다.

```bash
python scripts/evaluate_external.py --cache /tmp/ko-pii-external \
  --rank-start 0 --output /tmp/ko-pii-1.26.0-ranks-0.json
```

500/1000/1500/2000/2500도 같은 방식이며 최초 다운로드에만 `--download`를 사용합니다.
두 버전의 환경·결과 경로를 분리하고 이전 결과를 덮어쓰지 않습니다.

새로 매핑되는 열과 토큰 순서, bool/float 거부가 기존 파이프라인에 영향을 줄 수 있습니다.
[표 처리·전환 안내](../docs/STRUCTURED_PROCESSING.md), [양식 문법](../docs/SCOPED_RULES_AND_TRACE.md)과
실제 업무 자료의 미탐·과다 마스킹·출력 잔존·복원 권한을 확인해야 합니다. 현재 검사가
고객 환경의 사업 적용 승인이나 법적 익명성 판정을 대신하지 않습니다.
