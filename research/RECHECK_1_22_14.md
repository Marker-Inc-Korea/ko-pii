# 1.22.14 배포본 재검사

2026-10-27, 실제 PyPI 설치본, Python 3.12.3.
제품 커밋: `49af041856a97249de3784faa70500c60a38ff32`.

## 수정과 배포 확인

HWPX 텍스트 안의 탭·줄바꿈·비출력 표시 뒤 문자열이 추출에서 빠지던 문제를 수정했습니다.
문서의 일부만 탐지·변환한 뒤 성공할 수 있던 경로이며, OCR이나 원본 문서의 편집 기능을
추가한 것은 아닙니다. 탐지 규칙과 처리 정책도 이 릴리스에서 바꾸지 않았습니다.

- 새 회귀 검사 44개 중 기존 PyPI 1.22.13에서는 42개 실패, 2개 통과했습니다.
  수정 후에는 44개 모두 통과했습니다. 42개의 독립 버그를 뜻하지 않습니다.
- 실제 PyPI 1.22.14 전체 검사: 2,974개 통과, 15개 생략.
  생략은 로컬에서 설치하지 않은 선택 SDK와 범위 밖 분류기 검사입니다.
- 별도 경계 검사 88개 통과. 코어만 설치한 환경에서 추출·마스킹·Vault 복원 통과.
- 공개 HWPX 테스트 문서 두 개의 XML 텍스트와 추출 결과를 별도 대조했습니다.
  누락되던 탭 뒤 5개, 줄바꿈 뒤 2개 텍스트 구간이 보존됐습니다.
  자료는 [고정 리비전의 상류 테스트 자산](https://github.com/airmang/python-hwpx/tree/0fe42c0901da54bba41cb636c5c08b79de8cc6eb/tests/fixtures/hancom_saved)이며,
  직접 한컴 GUI에서 렌더링하거나 고객 문서를 검증한 결과는 아닙니다.
- [릴리스 CI](https://github.com/Marker-Inc-Korea/ko-pii/actions/runs/40452172745)는
  Python 3.10/3.12/3.14, Windows/macOS, 선택 RAG/MCP/Presidio, 합성 회귀,
  정적 검사와 배포 검사를 통과했습니다.
- PyPI에서 받은 wheel/sdist가 CI에서 테스트한
  [배포 명세](https://github.com/Marker-Inc-Korea/ko-pii/releases/download/v1.22.14/distribution-manifest.json)의
  커밋·SHA-256·크기와 일치했습니다. 테스트 집합은 중복되므로 통과 수를 합산하지 않습니다.

## 외부 고정 표본

[기존 프로토콜](external-protocol.json)을 그대로 사용했습니다. 외부 작성 합성 자료
K-PII-Bench Track A 500건, 14개 대응 라벨, 엄격한 문자 span 매처, STRICT/redact,
사용자 규칙·제외어·보조 모델 없음 조건입니다. 반복 평가한 회귀 표본으로,
새 블라인드 평가나 실제 고객 문서의 개인정보 제거율이 아닙니다.

| 지표 | 실제 PyPI 1.22.14 |
|---|---:|
| TP / FP / FN | 1036 / 826 / 841 |
| Precision / Recall / F1 | 0.5564 / 0.5519 / 0.5542 |
| 평가 대상 gold 구간 | 1,877 |
| 완전히 치환된 구간 | 943 |
| 미탐으로 남은 구간 | 723 |
| 정책으로 보존된 구간 | 200 |
| 일부만 치환된 구간 | 11 |

완전히 치환되지 않은 934개를 모두 같은 원인의 미탐으로 세면 안 됩니다.
정책상 보존과 부분 치환을 구분해야 합니다. 탐지 F1은 경계·라벨 일치를 평가하므로
출력에 실제로 남는 값의 비율과도 다릅니다. 미지원 upstream 라벨 4종은 이 점수에
포함되지 않으며, 이 표본에서는 그중 3종에 속하는 222개 구간이 별도로 집계됐습니다.

이 값은 실제 발급 번호의 검증률이나 고객 환경 재현율이 아닙니다. 체크섬·형식 조건과
합성 gold의 차이, ADDRESS 매핑 범위, 정책상 보존 여부를 따로 검토해야 합니다.
EMAIL/PHONE의 표본 재현율 1.0도 일반적인 무미탐 보증이 아닙니다.

직전 1.22.13 및 로컬 1.22.14 wheel과 데이터·프로토콜·실행기 해시, 라벨별·도메인별
집계, 출력 잔존 집계가 동일합니다. HWPX 파일 읽기는 이 텍스트 표본의 평가 경로가
아니므로 이번 파일 추출 수정이 탐지 점수를 개선했다고 주장하지 않습니다.

## 남은 적용 조건

패키지 회귀 검사는 통과했지만, 업무별 필수 라벨·입력 형식·미탐/오탐 허용 기준을 정한
독립 검증은 아직 필요합니다. 테스트가 많거나 체크섬을 사용한다는 이유만으로
임의의 문서를 자동 외부 전송해도 된다고 판단해서는 안 됩니다. Vault 접근 제어와
지원하지 않는 문서 객체 처리도 호출 애플리케이션의 설계 범위입니다.
