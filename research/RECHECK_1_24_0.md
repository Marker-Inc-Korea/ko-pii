# 1.24.0 이름 목록·상세주소·조밀한 문서 비용 재검사

2026-11-18, Python 3.12.3. 코어 규칙 기반 경로를 배포 1.23.1과 비교했습니다.
모델·OCR·분류기·외부 API나 새 코어 의존성은 추가하지 않았습니다.
아래 결과는 패키지 회귀 근거이며 실제 고객 업무의 운영 승인 자료가 아닙니다.

## 수정과 검증

- 명시적 한글 이름 필드에서 쉼표·슬래시·가운데점·하이픈·`&`로 연결한 값을 각각
  처리합니다. 대괄호/【】/Markdown 강조·코드 라벨과 같은 행의 라벨-값 셀을 인식합니다.
  같은 줄·셀의 지원 이름만 이어 처리하며 다른 기록이나 임의 문장으로 문맥을 넘기지 않습니다.
- 상세주소의 지하/지상 층, 영문·한글 동, `B1층`·`B101호`·`호실`, 연결 동호수를
  보완합니다. `3호선`·`101동작`의 접두사 오인과 숫자에 붙은 상세주소의 PERSON 오인도
  검사합니다. 명시적 사람 필드와 이미 확인한 이름의 우선순위는 유지합니다.
- 공개 API 경계 검사 165개를 같은 조건으로 실행했을 때, 기존 설치 wheel은 79개
  실패/86개 통과, 새 구현은 모두 통과했습니다. 문법·Unicode·좌표·출력·정책 조합을
  포함한 사례 수이며 독립 결함 수나 업무 정확도 지표가 아닙니다.
- 소스 전체 4,021개 통과/15개 생략, 별도 설치 wheel 4,006개 통과/30개 생략입니다.
  선택 의존성 생략을 통과로 합산하지 않습니다. 생성형 검사와 같은 검사의 반복 실행도
  새로운 운영 표본으로 계산하지 않습니다.
- 설치 wheel의 선택 RAG/MCP 검사 33개, 최소 MCP 1.28.1과 2.0.0의 실제 stdio 각
  19개가 통과했습니다. Presidio 규칙 연동은 6개 통과/환경 반대 조건 1개 생략입니다.
  README Python·텍스트/JSON CLI 예제, 합성 seed 0~3의 기존 회귀 하한도 통과했습니다.
- 린트와 전체 155개 소스의 타입 검사를 선택 MCP SDK 설치/미설치 환경에서 통과했습니다.
  중첩 구간·인접 거리·위치 마커 끝점의 조회는 독립 전체 순회 oracle과 생성형 입력으로
  대조했습니다. API·Vault 저장 형식·모드·기존 겹침 우선순위를 새로 정의하지 않습니다.

문법과 출력 전환 범위는 [확장과 설명](../docs/SCOPED_RULES_AND_TRACE.md),
[호환성](../docs/COMPATIBILITY.md), [변경 기록](../CHANGELOG.md)을 참고하세요.

## 조밀한 문서의 비용

같은 호스트에서 직접 패턴 탐지를 각 3회 실행한 `time.process_time()` 중앙값입니다.
모듈 가져오기 비용을 제외하고 GC는 활성 상태를 유지했습니다. 호출 전 GC를 수거해
측정 시작 상태를 맞췄습니다. 서비스 지연·파일 추출·전체 Anonymizer의 시간 상한은 아닙니다.

| 한 행의 입력 | 행 수 | 1.23.1 CPU 초 | 1.24.0 CPU 초 |
|---|---:|---:|---:|
| `주소: 서울특별시 강남구 테헤란로 152` | 500 / 2,000 | 0.0231 / 0.2722 | 0.0099 / 0.0386 |
| `생년월일: 1988-01-01` | 500 / 2,000 | 0.0088 / 0.1180 | 0.0042 / 0.0170 |
| `홍길동 010-1234-5678` | 500 / 2,000 | 0.0280 / 0.2314 | 0.0177 / 0.0706 |
| `성명: 김다은, 박보라` | 500 / 2,000 | 0.0301 / 0.1164 | 0.0200 / 0.0807 |

주소·생년월일의 반복 중복 순회를 정렬된 구간의 prefix-max 끝점 조회로,
이름의 위치 마커 근접 검사를 정렬된 끝점의 이진 조회로 바꿨습니다. 같은 행 수의
탐지 건수는 유지했지만, 건수만으로 이름 목록의 전체 치환을 증명하지는 않습니다.
실제 치환은 위 공개 API 검사에서 별도로 확인했습니다. 이 네 입력의 CPU 비용이
줄었다는 결과를 모든 입력에서 일정한 처리량을 보장한다는 뜻으로 사용하지 않습니다.

## 외부 합성 문서 회귀

[고정 프로토콜](external-protocol.json)의 K-PII-Bench Track A, CC-BY-4.0과 기존
리비전·해시·14개 대응 라벨·STRICT/redact를 유지했습니다. 4개 미대응 라벨과
upstream BIO 점수, 실제 발급 번호·고객 문서는 이 검증 범위가 아닙니다.

0~2499는 이미 관찰한 회귀 자료입니다. 제품 코드 동결 후 2500~2999를 설치 wheel로
확인했습니다. 같은 합성 코퍼스의 다른 순위이지 블라인드·고객 도메인 검증은 아닙니다.
개발 중 이 표본에 맞춰 개별 인명·주소를 사전에 추가하지 않았습니다.

| SHA-256 순위 (끝 제외) | 두 버전의 F1 | 두 버전의 완전히 치환되지 않은 gold 구간 |
|---|---:|---:|
| 0~500 | 0.5593 | 886 |
| 500~1000 | 0.5469 | 950 |
| 1000~1500 | 0.5549 | 911 |
| 1500~2000 | 0.5622 | 939 |
| 2000~2500 | 0.5582 | 939 |
| 2500~3000 | 0.5555 | 887 |

3,000건 전체에서 새/해소 strict FN·FP와 새/해소 출력 잔존은 모두 0개입니다.
집계뿐 아니라 문서·라벨·좌표별 변화를 비교했습니다. 이번 수정은 명시적 필드와
상세주소 문법·처리 비용 보완이며 이 표본의 탐지율을 개선하지는 않았습니다.
총 gold 11,522개 중 완전히 치환되지 않은 구간은 두 버전 모두 5,512개입니다.
정책상 보존·부분 치환도 포함하므로 이 수치를 개인정보 유출률로 해석하면 안 됩니다.
자유 문장 PERSON/ADDRESS의 낮은 성능이 해결됐다는 근거로 사용하지 않습니다.

## 재현과 제품 동결

```bash
python scripts/evaluate_external.py --cache /tmp/ko-pii-external \
  --download --rank-start 0 --output /tmp/ko-pii-1.24.0-ranks-0.json
python scripts/evaluate_external.py --cache /tmp/ko-pii-external \
  --rank-start 2500 --output /tmp/ko-pii-1.24.0-ranks-2500.json
```

500/1000/1500/2000도 같은 방식이며, 버전별 환경과 출력 경로를 분리합니다. 기존
결과를 덮어쓰지 않고 `--download` 없는 실행은 네트워크·모델을 호출하지 않습니다.
앞 다섯 표본의 선택 문서 해시는 [1.23.1 기록](RECHECK_1_23_1.md)의 표본과 같습니다.

소스와 설치 wheel의 제품 `.py` 155개에 대해 패키지 상대 POSIX 경로 순으로
`경로 + NUL + 파일 내용 + NUL`을 결합한 SHA-256이 일치합니다:
`08b0242fc20a99fb4a840fbc6a37ca8130e97df9e6792ef5f32710ff241215d2`.
외부 확인 후 제품 코드는 변경하지 않았습니다.

실제 사업 적용의 완료 조건은 여전히 업무별 필수 라벨·재현율 기준·잔존/과다 마스킹,
지원 문서의 추출 범위와 복원 권한을 실제 자료로 검증하는 것입니다.
[도메인 평가](../docs/DOMAIN_EVALUATION.md) 절차를 사용하고 고객 원문·Vault를 공개
저장소나 버그 보고에 올리지 마세요. 이 릴리스만으로 모든 업무의 운영 승인을 선언하지 않습니다.
