# 1.22.18 이름 필드와 금융 경계 재검사

2026-11-18, Python 3.12.3. 실제 PyPI 1.22.17과 로컬 1.22.18 후보를 비교했습니다.
코어 규칙 기반 경로이며 사용자 제외어, 추가 규칙, 보조 모델은 사용하지 않았습니다.
이 문서는 고객 업무 승인이나 모든 개인정보 제거를 보증하는 자료가 아닙니다.

## 수정 범위와 회귀 검사

- 명시적 이름 필드의 끝 음절 누락과 접미사에 의한 거부를 수정했습니다. 경계가 분명한
  2~4음절 값을 통째로 다루고, 문장 속 이름+조사는 분리합니다. 모호한 단독 필드에서는
  조사까지 가려질 수 있습니다. [이름 필드 계약](../docs/SCOPED_RULES_AND_TRACE.md)을 참고하세요.
- 한글/숫자 줄 경계를 기본 보존하여 다음 행의 값과 붙이지 않습니다. 계좌 뒤 금액,
  사업자번호 구분자와 카드 그룹 형식도 수정했습니다. 번호의 실제 발급 여부나 OCR은
  검증하지 않습니다. [번호 검증 범위](../docs/IDENTIFIER_VALIDATION.md)를 참고하세요.
- 문장 경계 인덱스와 접미사 처리 최적화는 기존 문맥 점수의 의미를 유지합니다.
  성능 검사는 GC를 끄거나 시간 상한을 높이지 않고 측정 시작 조건을 맞췄습니다.
- 소스와 별도 설치 wheel은 각각 전체 3,434개 통과, 13개 생략했습니다. sdist에 포함된
  자산만으로는 3,424개 통과, 23개 생략했으며 문서 예제도 통과했습니다. 이는 같은
  테스트의 중복 실행이며 숫자를 합쳐 독립 검사 수로 주장하지 않습니다.
- 생략은 선택 ML/Presidio/RAG 의존성과 sdist에 미포함한 연구 데이터 때문입니다.
  별도 RAG/MCP 설치 환경의 29개, 최소 MCP 1.x의 실제 stdio 17개도 통과했습니다.
  SDK 2.x 환경 전체 153개 소스 파일 및 SDK 1.x 어댑터 경계의 타입 검사도 통과했습니다.

위 숫자는 제품 수정 동결 시점의 로컬 결과입니다. 이후 평가 실행기의 순위 선택 검사는
별도로 추가했고, 배포 승인 여부는 해당 태그의 CI와 배포 명세를 확인해야 합니다.

## 외부 합성 표본 비교

자료는 [K-PII-Bench 고정 리비전](https://huggingface.co/datasets/woohyun212/k-pii-bench/tree/844f92f7beba98fa964f957ba324017e82451701)의
Track A, CC-BY-4.0입니다. [원본 해시와 라벨 대응 프로토콜](external-protocol.json)을
유지하고 SHA-256(doc_id), doc_id 순서의 서로 겹치지 않는 500건씩을 사용했습니다.
14개 대응 라벨의 엄격한 문자 span 점수와 STRICT/redact의 실제 출력 상태를 함께 봅니다.

0~499는 반복 측정한 기존 회귀 표본입니다. 500~999도 개발 중 비교한 추가 회귀 자료이며,
그 오류 양상을 점검했습니다. 1000~1499는 이번 제품 코드 동결 후 별도 설치 wheel로
확인했습니다. 동일한 합성 코퍼스의 다른 순위일 뿐, 다른 업무 도메인이나 과거 노출이
없었던 블라인드 시험이라고 주장하지 않습니다. 확인 표본을 본 뒤 제품 규칙은 바꾸지 않았습니다.

| 해시 순위 (끝 제외) | 1.22.17 F1 | 1.22.18 F1 | 완전히 치환되지 않은 구간 (전 → 후) |
|---|---:|---:|---:|
| 0~500 | 0.5542 | 0.5523 | 934 → 922 |
| 500~1000 | 0.5405 | 0.5398 | 997 → 985 |
| 1000~1500 | 0.5448 | 0.5438 | 968 → 957 |

**탐지 F1이 개선됐다고 해석하면 안 됩니다.** 단독 필드값 전체를 보호하면서 gold의
이름보다 한 음절 길어지는 경우도 strict span에서는 FP/FN입니다. 기존보다 출력에
완전히 치환되지 않은 구간은 각 표본에서 12/12/11개 줄었고, 이전에 완전히 치환됐던
gold가 새로 남는 경우는 이 세 표본에서 없었습니다. 개인정보가 아닌 주변 문자열을
더 가릴 가능성은 별도이며, 확인 표본의 새 FP 12개/해소 FP 8개도 숨기지 않습니다.

1000~1499 확인 표본의 1.22.18 결과는 TP/FP/FN = 1006/793/895입니다.
gold 1,901개 중 완전 치환 944, 미탐 751, 정책 보존 195, 부분 치환 11개입니다.
정책 보존과 미탐은 다른 원인입니다. 미지원 upstream 라벨 4종은 이 점수 밖입니다.

| 확인 표본 라벨 | TP | FP | FN | Recall |
|---|---:|---:|---:|---:|
| PERSON | 206 | 674 | 516 | 0.2853 |
| ADDRESS | 23 | 6 | 63 | 0.2674 |
| ACCOUNT | 23 | 0 | 56 | 0.2911 |
| CARD | 5 | 0 | 34 | 0.1282 |
| RRN | 142 | 0 | 75 | 0.6544 |
| PHONE | 204 | 4 | 0 | 1.0000 |
| EMAIL | 208 | 0 | 0 | 1.0000 |

형식/체크섬 검사와 합성 gold의 차이, 위치 라벨의 대응 범위도 결과에 영향을 줍니다.
PHONE/EMAIL의 표본 recall 1.0을 다른 문서의 무미탐 보증으로 옮길 수 없습니다.
특히 자유 서술의 PERSON/ADDRESS와 고객 환경의 식별번호 재현율 검증은 남아 있습니다.

## 재현

```bash
python scripts/evaluate_external.py --cache /tmp/ko-pii-external \
  --download --rank-start 0 --output /tmp/ko-pii-ranks-0-500.json
python scripts/evaluate_external.py --cache /tmp/ko-pii-external \
  --rank-start 500 --output /tmp/ko-pii-ranks-500-1000.json
python scripts/evaluate_external.py --cache /tmp/ko-pii-external \
  --rank-start 1000 --output /tmp/ko-pii-ranks-1000-1500.json
```

비교할 두 버전은 분리된 환경에 설치하고 같은 실행기를 사용합니다. 다른 출력 파일을
지정해야 하며 기존 결과를 덮어쓰지 않습니다. 제품 스크립트는 자료를 자동 다운로드하거나
규칙을 학습하지 않습니다. 상세 결과에는 원문 좌표와 문서 해시가 있어 공유 전에 검토하세요.

- 제품 `.py` 파일의 경로/내용을 결합한 SHA-256:
  `fbe312cfd8996ddb484420cf4b228088eee4b67b84cb1c6a7740995c77ac7f39` (소스/wheel 동일)
- 0~500 선정 문서 해시: `b6130e61877ce1519754580edddaa17dd903d735e80d57fc2474a26e32c6aabe`
- 500~1000 선정 문서 해시: `af646556f5c486af4def3fa5e7c9f2a0b96596f1880a5039ec7dd08f0a4eb537`
- 1000~1500 선정 문서 해시: `e8716302cc3974eb8d957cead0cadcba8556d7d780fd482c0c4527d248fe16ea`

업무 적용 승인은 [도메인 평가](../docs/DOMAIN_EVALUATION.md)에서 입력 형식·필수 라벨·
실제 출력의 잔존/오탐 기준을 정한 뒤 판단해야 합니다. 일반 합성 점수나 검사 통과 수가
그 승인을 대신하지 않습니다.
