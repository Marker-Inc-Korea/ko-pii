# 외부 합성 평가: 첫 측정과 해석

2026-10-26, PyPI ko-pii 1.22.0 코어, Python 3.12.3.
이번 1.22.1 정비에서는 탐지 규칙이나 기본 정책을 변경하지 않습니다.
새로 빌드해 설치한 [1.22.1 결과](external-1.22.1-summary.json)도 같은 데이터 해시에서
라벨별·도메인별 TP/FP/FN과 출력 잔존 집계가 모두 동일했습니다.

## 조건

- [고정 프로토콜](external-protocol.json): K-PII-Bench의 Track A 28,142건 중
  SHA-256(doc_id) 순서로 500건 선택. 외부 작성자의 합성 데이터이며 실고객 문서는 아닙니다.
- 데이터 리비전, 원본 143,005,610바이트와 SHA-256을 다운로드 후 확인했습니다.
- 18개 source 라벨 중 의미를 대응한 14개만 채점합니다. 표본에는 제외 라벨 222개 span이 있습니다.
- ko-pii strict 문자 span 매처입니다. upstream BIO 공식 점수, 옛 KDPII 점수와 직접 비교할 수 없습니다.
- STRICT/redact, 사용자 규칙·제외어·모델 없음. 결과를 본 뒤 규칙이나 표본을 조정하지 않았습니다.
- [기계 판독 요약](external-1.22.0-summary.json)에 모든 라벨과 12개 도메인의 지표,
  출력 잔존 집계, 프로토콜/실행 스크립트/전체 로컬 보고서의 해시를 포함합니다.

정답 위치의 실제 출력은 938개 완전 치환, 723개 미탐으로 잔존,
206개 탐지와 겹치지만 정책에 따라 잔존, 10개 일부 위치만 치환됐습니다.
따라서 939개가 완전히 치환되지 않았습니다. 이 숫자는 합성 정답 span 기준의 상태이며
실제 사고 건수나 고객 환경의 유출 확률이 아닙니다.

STRICT도 모든 탐지값을 무조건 지우는 모드는 아닙니다. 예를 들어 이 실행에서 URL 102개와
VEHICLE 42개는 정책에 따라 남았습니다. 결과의 `retained_by_policy`는 정확한 라벨 일치가
아니라 해당 위치와 탐지의 겹침을 기준으로 하므로 strict TP와 같은 지표가 아닙니다.

## 무엇을 말할 수 있나

이 조건에서 EMAIL/PHONE은 강했지만 RRN/CARD도 미탐이 있었으며 PERSON/ADDRESS는 약했습니다.
구조적 식별자라는 이유만으로 항상 완전히 제거된다고 주장하지 않습니다.
미탐 원인이 형식·체크섬·경계·gold 정의 중 무엇인지는 별도의 사례 검토가 필요합니다.
이를 확인하지 않고 데이터가 틀렸다거나 실제 성능이 더 좋다고 보정하지 않습니다.

정밀도와 재현율을 함께 보고, 배포 목적에 맞는 출력 정책을 검증해야 합니다.
숫자가 1.000인 라벨도 표본 수가 작으며 보편적 정확도의 보증이 아닙니다.
같은 작성자의 합성 템플릿들이므로 표본의 span들을 독립 관측이라고 가정한
단순 신뢰구간이나 실환경 우열 순위를 제시하지 않습니다.

## 재현

`scripts/evaluate_external.py`를 설치한 패키지 환경에서 실행합니다.
첫 보고서는 실제 PyPI 1.22.0으로 생성했으며, 과거의 완전한 비노출을 증명하는
블라인드 벤치마크라고 부르지는 않습니다.

```bash
python scripts/evaluate_external.py --cache /tmp/ko-pii-external --output /tmp/external-report.json --download
python scripts/summarize_external.py /tmp/external-report.json /tmp/external-summary.json
```

재실행 시 시간·패키지 버전과 전체 파일 해시는 달라질 수 있습니다.
동일 입력/코어의 비교에는 dataset 해시, 설정, TP/FP/FN 및 출력 상태를 사용하세요.
원본 데이터와 문서별 span 보고서는 저장소에 재배포하지 않습니다.
