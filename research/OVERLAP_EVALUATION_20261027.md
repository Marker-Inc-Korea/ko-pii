# 정책 적용 순서 수정 후 고정 회귀 평가

2026-10-27, ko-pii 1.22.6 설치 wheel과 1.22.7 수정 소스, 양쪽 Python 3.12.13.

## 수정 범위

내장 탐지기의 합성 재현 입력 `계좌번호: 9001011234567`에서 BALANCED 정책이
차단해야 할 ACCOUNT 후보를 앞선 RRN 후보가 숨겼습니다. 위험도 우선으로 후보를
먼저 제거한 뒤 정책을 적용했기 때문입니다. 1.22.7은 후보를 보존하고 병합 정책과
처리 임계값을 적용한 다음 BLOCK 후보를 우선 선택합니다.

같은 후보 선택 문제는 다른 라벨과 모드에서도 생길 수 있습니다. 개별 데이터 행에
맞춰 패턴이나 임계값을 바꾸지 않고 처리 순서를 수정했습니다. 탐지 전용 detect_all의
위험도 우선 계약은 유지하며, 이번 비교는 실제 Anonymizer 출력 경로의 결과입니다.

## 동일 표본 비교

[고정 프로토콜](external-protocol.json)의 K-PII-Bench Track A 합성 자료 500건,
대응 라벨 14종, STRICT/redact, 사용자 제외어/보조 모델 없음, strict 문자 span 매칭입니다.
표본, 데이터 및 실행 스크립트 해시가 같습니다. 이미 공개 측정한 표본이므로 새로운
블라인드 홀드아웃 검증으로 해석하지 않습니다.

| 지표 | 1.22.6 | 1.22.7 |
|---|---:|---:|
| TP / FP / FN | 1031 / 832 / 846 | 1036 / 826 / 841 |
| Precision / Recall / F1 | 0.5534 / 0.5493 / 0.5513 | 0.5564 / 0.5519 / 0.5542 |
| 완전히 치환되지 않은 gold span | 939 | 934 |

- 기존 미탐 5건이 해결됐고 새 미탐은 없었습니다.
- 기존 오탐 7건이 해소됐지만 ADDRESS 오탐 1건이 새로 생겼습니다.
- 이전에 완전히 치환했던 구간이 새로 남는 출력 회귀는 없었습니다. 기존에 남던 5개
  정답 구간은 완전히 치환됐고, 별도 1개 구간은 정책 보존에서 부분 치환으로 바뀌었습니다.
- 최종 출력 상태는 replaced 943, missed 723, retained_by_policy 200,
  partially_replaced 11입니다. 전체 gold는 1,877개입니다.

[기계 판독 요약](external-1.22.7-summary.json)에 환경, 라벨/조건별 집계, 해시를
기록합니다. 원문과 개별 문서 데이터는 재배포하지 않습니다.

## 적용 판단

이는 잘못된 처리 순서를 바로잡은 결과이지, 모든 개인정보를 제거한다는 보장이 아닙니다.
후보를 바르게 선택해도 탐지기 자체의 미탐, 정책에 따른 보존, 불완전한 경계는 남습니다.
이번 수정은 새 ADDRESS 오탐도 만들었으므로 고객 문서에서 필요한 라벨별 미탐/오탐과
최종 출력을 함께 평가해야 합니다. 934개를 실제 고객 개인정보 유출 건수로 해석해서도
안 됩니다. [이전 평가의 한계](EXTERNAL_EVALUATION_20261026.md)도 그대로 적용됩니다.
